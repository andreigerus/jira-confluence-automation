# Instructions: How to Fill Out the Status Report

Use [template.md](./template.md) as the starting point for each new status report. Copy it and rename the copy (e.g. `2026-08-10-status-report.md`).

## Field-by-field guidance

- **Project**: The full name of the project or workstream being reported on.
- **Reporting Period**: The date range this report covers (e.g. a week or sprint).
- **Prepared By**: Your name or the name of the person compiling the report.
- **Date**: The date the report is published/sent, not the end of the reporting period.

### Summary
Write one or two sentences giving a reader who skims only this section a clear picture of where things stand.

### Status
Choose one of:
- **On Track** – work is proceeding as planned, no significant blockers.
- **At Risk** – there are concerns that could affect scope, schedule, or budget if unaddressed.
- **Delayed** – the project has already slipped against its plan.

### Accomplishments
List concrete, completed items from the reporting period. Avoid vague statements like "made progress" — state what was actually finished.

### Planned Next
List the specific items you intend to complete in the next reporting period.

### Risks & Issues
Add a row for each active risk or issue:
- **Risk/Issue**: A short description.
- **Impact**: High, Medium, or Low.
- **Mitigation**: What is being done (or planned) to address it.
- **Owner**: Who is responsible for resolving it.

Remove the placeholder row if there are no risks or issues to report.

### Metrics
List any quantitative measures relevant to the project (e.g. budget spent, tasks completed, defect count). Remove this section if not applicable.

### Notes
Use for anything that doesn't fit the sections above, such as dependencies on other teams or upcoming decisions needed from stakeholders.

## Tips
- Keep language concise and factual.
- Only include sections that are relevant; delete unused rows/sections rather than leaving placeholders.
- See [example.md](./example.md) for a completed sample report.
